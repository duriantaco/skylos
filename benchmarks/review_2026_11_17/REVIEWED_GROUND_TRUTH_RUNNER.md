# Reviewed source truth runner

`run_reviewed_ground_truth.py` performs static scans only after validating a freeze seal. Its scores describe selected independently reviewed facts, not whole-repository precision or recall. The study is a post-scan source review; earlier scans prevent calling it a new blind study.

The seal must use `status: frozen_after_independent_review`, an ISO `frozen_at`, a hashed manifest, and hashed review artifacts. Artifact paths are relative to the seal directory. Each review binds its draft file and SHA-256, identifies its reviewer, and contains a per-fact `verdicts` entry with an agreed or resolved truth. Draft author and independent reviewer must differ. If an immutable draft lacks an author field, the review must explicitly name `draft_author`.

Every final fact must link its resolved review. The gate checks repository identity, commit, reviewed source bytes, fact identity, truth, and source range. Reviewer-added consumer evidence is also bound to its source hashes. A reviewer may explicitly approve a `recommended_match_span`. All reviewed facts must remain represented, including unknown and intentionally retained facts. Explicit reviewer eligibility decisions cannot be changed to add negative credit or exclude positive misses. Pending coverage remains a runtime condition. Changing a declared or reviewer-approved finding category or owner class is rejected.

The final manifest may derive missing scoring metadata from source: imports use `unused_imports`, class declarations use `unused_classes`, and methods use `unused_functions`. Such derivation must be documented by review; it does not change semantic truth. A security fact without an implemented rule may retain `rule_id: null` only when explicitly unscored. No rule is invented to make an observation count.

Before any analysis, `verify_checkout` checks every target and source pin; it runs again after each analysis. Analyzer options contain no labels, symbols, expected answers, or review content. Isolated analysis disables target execution, secrets, SCA, quality, AI checks, custom rules, and trace inputs. The explicitly selected Go engine is hashed and preserved through environment isolation. Existing output paths are refused.

Scoring matches dead-code category, file, source line/range and symbol identity, preserving qualified owners where supplied. A simple method symbol with `owner_class` requires that owner in both finding and extraction matches; an unrelated same-name method cannot satisfy it. A warning that removes the owning class or file also conflicts with a known-used member. Security findings require the same file, range and rule. Unscored null-rule semantic facts preserve any warnings at the labelled site as observations only.

Quiet known-used facts require an exact parsed definition. Quiet security-safe facts require parsed evidence in the same file. Missing extraction in these negative controls is unscored, not a true negative. Source-proven unused/unsafe positives missing from an otherwise complete scan are false negatives; missing extraction must not erase positive truth. Incomplete scans earn no accuracy credit. Explicitly retained unused facts, unknowns, and unsupported sites stay separate and retain matching observations.

The output records freeze/run times, analyzer source and Go binary hashes, raw-report hashes, per-fact evidence matches, TP/FP/FN/TN counts and unscored reasons. It does not classify unlabelled findings as false positives or quiet unlabelled code as true negatives.

Validation used synthetic JSON and mocked analyzers only: `test/test_reviewed_ground_truth_runner.py` and the separate reviewer’s `test/test_reviewed_ground_truth_audit.py`. No real checkout scan was run while developing this runner. The current focused result is in `reviewed_ground_truth_runner_tests.txt`.
