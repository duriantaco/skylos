# Frozen tiny-http security miss

The frozen `tiny-example-file-read` label remains a `SKY-D215` false negative in both saved runs. This is a gap in Rust's framework input-source model. The file was parsed: both reports extract `get_content_type` at line 8 and `main` at line 27, report 36 scanned files and no analysis errors, and contain no security finding in `examples/serve-root.rs`. Their four security findings are unrelated workflow-policy observations.

The source label was agreed before these runs. In the pinned example, a received request supplies the URL used to construct the path and open the file at line 42; the existing source has no serving-root restriction. This remains an intentional example source risk, not a claim about a deployed service or the tiny-http core library. No additional positive label or exploit reproduction was introduced.

The detector already supports `std::fs::File::open` (`rust/danger.py:16–29,797–812`) and propagates existing source facts through standard path constructors (`817–818`). Its explicit request extractor models cover Axum and Actix (`64–68,405–420`), with environment sources at `34,782–783`. It has no corresponding tiny-http server/request/URL provenance model. Generic methods combine existing receiver/argument source facts (`1060–1061,1145–1158`); they do not invent a missing source. Naming a local variable `url` does not help because the name heuristic applies to function parameters (`425–433`). `UNKNOWN` has an empty source set, and the filesystem warning requires a nonempty one (`_security_bindings.py:8–27`). This missing input model is sufficient to explain the miss; it is not evidence that parsing failed or the frozen label was incorrect.

The relevant Rust detector files exactly match the hashes recorded by both runs. The miss therefore predates, and survives, the precision changes reviewed in this session. A complete scan describes execution/parse completeness; it does not prove complete framework-security coverage. Keep this FN in the frozen denominator.

The existing default corpus covers command-line path input (`rust-path-argument`), a recognized request extractor (`rust-path-axum-extractor`), and a local extractor lookalike negative (`rust-path-local-extractor-lookalike`). Those controls do not cover this missing framework source. A future extension needs actual provider/receiver provenance and paired fixed-data, local-lookalike, and contained-path controls. Marking every `.url()` or `.recv()` call as untrusted would increase noise.

The initial no-SDK reviewed_before/after arms also have ten quiet negative labels without exact extraction. Explicit-SDK reruns restore two Go extractions and leave eight such gaps. They remain unscored, earn no true-negative credit, and are not ten proven positive misses. No frozen artifact or detector was changed during this diagnosis.
